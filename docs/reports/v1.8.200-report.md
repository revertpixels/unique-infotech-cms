## 1. What Went Wrong With Kids Receipt Numbers (`UK26AD-UKKKKK-0005`)

- **Youth Centre** generates receipt numbers from each branch's own short `code` (for example `BYCTC` -> `UI26AD-BYCTC-0001`).
- **Unique Kids** has only **one** school, co-located at **Head Office** (`branchId: 'HO'`, `branchCode: 'HO'`). However, back in `v1.8.69`, an editable **Receipt code (Kids)** input (`settings/org_config.receiptCode`) was added to `#/org` (accepting any 2–12 letters) and `school-admissions.page.js` + `school-billing.js` used `org_config.receiptCode` **ahead of** the built-in `'HO'` code (`centreCode = configuredCode || 'HO'`).
- When `'UKKKKK'` was saved into `settings/org_config.receiptCode` in the live database during testing/setup, every subsequent new Kids receipt pulled `'UKKKKK'` into the centre segment (`UK26AD-UKKKKK-0005`).
- **Fix in `v1.8.200`:**
  - All **new** Kids receipts in [school-admissions.page.js](file:///C:/Users/Asus/WebstormProjects/unique-infotech-cms/public/js/pages/school-admissions.page.js) (`AD`), `recordKidsBillPayment` (`MN`), and `upgradeKidsPackage` (`UP`) in [school-billing.js](file:///C:/Users/Asus/WebstormProjects/unique-infotech-cms/public/js/utils/school-billing.js) now always use Kids' Head Office code **`HO`** (`UK26AD-HO-0001`, `UK26MN-HO-0001`, `UK26UP-HO-0001`), ignoring any stale value in `settings/org_config.receiptCode`.
  - `#org-receiptCode` in [org-details.html](file:///C:/Users/Asus/WebstormProjects/unique-infotech-cms/public/pages/org-details.html) & [org-details.page.js](file:///C:/Users/Asus/WebstormProjects/unique-infotech-cms/public/js/pages/org-details.page.js) is now read-only **`HO`** so admins cannot accidentally misconfigure it, and opening `#/org` does not trigger a false unsaved-changes state.
  - **Existing receipts untouched:** Previously saved receipt numbers (including `UK26AD-UKKKKK-0005`) are preserved as-is in Firestore and continue to render normally via [school-receipt.js](file:///C:/Users/Asus/WebstormProjects/unique-infotech-cms/public/js/utils/school-receipt.js).

## 2. All Other Changes (Plain English)

1. **ONE Shared Admission Success Popup (`promptAdmissionSuccess`) for Youth & Kids**
   - Removed the separate 4-button `promptKidsAdmissionSuccess` modal in [payment-popup.js](file:///C:/Users/Asus/WebstormProjects/unique-infotech-cms/public/js/components/payment-popup.js) and replaced it with ONE shared `promptAdmissionSuccess` popup used after **Youth Paid**, **Kids Paid**, and **Kids No-payment** admissions.
   - Immediately upon admission save, the receipt / admission slip route (`#/admissions/<id>/receipt` or `#/school-admissions/<id>/receipt`) opens **behind the popup**.
   - **Summary box:**
     - **Paid (Youth & Kids):** Receipt No., Student, Fee Head / Level, Amount Paid, Payment Mode (plus optional TXN ID), Date.
     - **Kids No payment:** Slip No., Student, Level, `₹0 (No payment) – <reason>`, `Monthly ₹X from <month>`, Date (no Payment Mode row).
   - **Exactly 3 icon buttons in order:**
     1. **Print receipt** (`Print slip` for Kids no payment) with printer icon -> closes popup, waits until the background receipt/slip renders cleanly in `#view`, then calls `window.print()`.
     2. **Admit another** (`user-plus` icon) -> closes popup and opens a fresh blank admission form (`#/students?new=1` or `#/school-students?new=1`; added `?new=1` support in [school-admissions.page.js](file:///C:/Users/Asus/WebstormProjects/unique-infotech-cms/public/js/pages/school-admissions.page.js)).
     3. **Done** (`check` icon) -> closes popup only, revealing the receipt / slip preview behind it.
   - Monthly fee payments, installments, and Kids Level Upgrades keep **"Payment Recorded!"** (`Open Receipt`, `Print`, `Done`) unchanged. Kids **"Confirm admission"** popup before No-payment admissions is also kept.

2. **Fixed All Broken Characters (``) & Encoding Across the Whole Repo**
   - Replaced raw Windows-1252 byte `0x97` in [ui-datepicker.js](file:///C:/Users/Asus/WebstormProjects/unique-infotech-cms/public/js/components/ui-datepicker.js) and every `\uFFFD` (``) across 12 source files (`school-admissions.page.js` including `"New admission · not submitted"`, `"Existing admission · payment unchanged"`, `·` separators, and `—` placeholders; plus file headers/comments in 11 other Kids & receipt modules) with clean UTF-8 without BOM.
   - Verified `hasBom: []`, `invalidUtf8: []`, and `mojibake: []` across all `.html`, `.js`, `.css`, `.md`, and `.json` files in the project (excluding literal test-check mentions in historical progress-log lines).

3. **Responsive Popup Overflow Fixes (`360px`, `768px`, Desktop)**
   - Updated [list-page.css](file:///C:/Users/Asus/WebstormProjects/unique-infotech-cms/public/css/components/list-page.css), [pay-fees.css](file:///C:/Users/Asus/WebstormProjects/unique-infotech-cms/public/css/pages/pay-fees.css), and [student-profile.css](file:///C:/Users/Asus/WebstormProjects/unique-infotech-cms/public/css/pages/student-profile.css):
     - Added viewport max-height & vertical scroll (`max-height: min(92dvh, calc(100vh - 24px))`, `overflow-y: auto; overflow-x: hidden;`) on `.pf-success-modal`.
     - Stacked `.pf-success-actions` and `.adm-view-foot` buttons full-width cleanly on narrow screens (`<= 480px`) and allowed wrapping cleanly at medium widths.

     - Compacted `.adm-view-head` / `.adm-view-body` mobile padding and added `overflow-wrap: anywhere` on `.pk-current-badge` & `.pf-success-val`.
