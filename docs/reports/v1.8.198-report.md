## 1. What Changed (Plain English)

1. **Kids Level Upgrade Modal (`openKidsUpgradePackageModal`) Uses the Shared Payment Popup**
   - Updated `openKidsUpgradePackageModal` (`public/js/utils/school-break-modals.js`) so whenever a level upgrade / package change has an extra amount `> 0` due now, clicking **Upgrade Package** opens `openPaymentPopup` (**Collect Upgrade Fee**) instead of saving immediately.
   - If the admin clicks **Cancel** (or closes the payment modal via backdrop / `Escape` / `X`), **nothing is written to Firestore**, and the Upgrade modal re-opens with all chosen fields preserved (selected **New level**, **New batch**, **Upgrade admission fee option**, and **First monthly billing month**).
   - When confirmed, `upgradeKidsPackage` (`public/js/utils/school-billing.js`) executes atomically inside `runTransaction`: generates a sequential Kids upgrade receipt number (`UK<YY>UP-<CENTRE>-<NNNN>`), stores `mode`, `paymentMethod`, `txnId`, and `remarks` on both the `payments` (`type: 'UPGRADE'`) document and the `packageHistory` upgrade entry, updates `enrolments` and unpaid future `bills`, and prompts the receipt modal (`Open Receipt` / `Print` -> `#/payments/<studentDocId>/<paymentId>/receipt?from=profile`).
   - Updated `buildKidsPaymentLedger` (`public/js/utils/school-billing.js`) so `UPGRADE` payment rows link directly to `#/payments/<studentDocId>/<paymentId>/receipt?from=school-payments` and preserve saved payment mode (`p.mode || p.paymentMethod`).
   - Updated `payment-receipt.page.js` so `Level Upgrade` receipts display `Level Upgrade (Full Admission)` vs `Level Upgrade Difference` accurately based on `payment.paymentMode`.

2. **Transaction / Reference ID Required for All Non-Cash Modes (Youth & Kids)**
   - Updated `public/js/components/payment-popup.js`:
     - **Cash:** Transaction / Reference ID remains disabled (`N/A for Cash`), cleared, and optional (`required = false`).
     - **Non-cash (`UPI`, `Card`, `Bank Transfer`, `Cheque`):** Transaction / Reference ID is now marked **\* (Required)** (`txnInput.required = true`). Clicking **Confirm & Record Payment** with an empty or whitespace-only ID is blocked in **both Youth and Kids**, displays a clear inline field error (`Transaction / Reference ID is required for <Mode> payments.`) plus toast error, and focuses the input. Entering text or switching back to Cash clears the validation state.
