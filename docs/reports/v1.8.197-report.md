## 1. What Changed (Plain English)

1. **Shared Payment Popup for Kids Admissions (`#/school-students`)**
   - Removed the old `"I confirm received"` tick box (`#adm-confirm-received-wrap`, `#adm-confirmReceived`) from `public/pages/school-admissions.html` and `public/js/pages/school-admissions.page.js`.
   - When admitting a new Kids student with **Full** or **Difference** payment and charge `> 0`, clicking **"Admit student"** validates the form + uploads (and warns if another active Kids student already has the same phone + level), then opens the shared payment modal (`components/payment-popup.js`) **before saving**.
   - Nothing is written to Firestore until the payment modal is confirmed. Clicking **Cancel** closes the modal and leaves the admission form open and filled.
   - Inside the popup, admins get the exact same payment mode options (`Cash`, `UPI`, `Card`, `Bank Transfer`, `Cheque`), Transaction / Reference ID rules (`N/A for Cash`, `Optional` for non-cash — see note in Section 4), and fixed read-only payment date (`todayISO()`).
   - **No payment** (`charge === 0`) skips the payment popup and saves immediately as before.

2. **Shared Payment Popup for Kids Monthly Fees (`#/school-fees`, `#/school-fee-payment`, `#/school-pending`, `#/students/<id>`)**
   - Replaced disparate monthly bill collection paths with `openPaymentPopup` backed by `recordKidsBillPayment` (`public/js/utils/school-billing.js`) inside an atomic Firestore transaction (`tx`):
     - Reads open bills via `fetchOpenKidsBillsForStudent` (oldest-first selectable `BILL_<id>` dropdown), shows monthly fee + late fine + payable total, shows the Super Admin-only late-fine waiver box + reason selector when `lateFee > 0`, generates a sequential Kids monthly receipt number (`UK<YY>MN-<CENTRE>-<NNNN>`), records `mode`, `txnId`, and `remarks` on both root `payments` and `bills`, creates a `waivers` doc when a fine is waived, and dispatches `uic:data-mutated`.
   - Wired `#/school-fees` Pay button, `#/school-pending` Kids `Collect` button, Student Profile `+ Record Payment` & row `Collect` buttons, and `#/school-fee-payment` (`#sk-pay-form` fix + numeric amount + popup launcher) to this single flow.

3. **Receipts, Payment History & Student Profile Show Payment Mode & Transaction ID**
   - **Kids Admission Receipt (`school-receipt.js`, `school-admission-receipt.page.js`, `school-receipt-pdf.js`):** Added `paymentMethod`, `paymentMethodLabel`, `txnId`, and `paymentRemarks` to `buildSchoolReceiptData`, rendering a **Payment mode** row + TXN reference in both HTML print view and PDF export. Also fixed broken `#uk-back` / `#uk-nf-back` links (`#/school-students`), fixed `#uk-profile-btn` (`#/students/<id>`), and added `?print=1` auto-print.
   - **Kids Monthly / Upgrade Payment Receipt (`payment-receipt.page.js`):** Added `ctx === 'school'` support reading root `payments/<id>` + unpaid `bills` balance, rendering `renderKidsReceiptHTML` with **Payment mode**, **Transaction / Ref ID**, remarks, late fine / waiver note, and open bills balance (with `Download PDF` + `Print`), plus read-only access for `school_head` on Kids receipts and `Back` routes for `school-fees` / `school-pending`. Youth `renderReceiptHTML` was untouched.
   - **Kids Payment History (`school-billing.js`, `report.service.js`, `payments.page.js`):** Stopped assuming `'cash'` on admission entries; preserves saved `mode` / `paymentMethod`, `txnId`, and `paymentRemarks`, shows desktop Mode badges (`Cash`, `UPI`, `Card`, `Bank Transfer`, `Cheque`) + Details modal / mobile Transaction ID, and emits `#/payments/<studentDocId>/<paymentId>/receipt?from=school-payments` on monthly fee rows.
   - **Kids Student Profile (`student-profile.html`, `student-profile.page.js`):** Added `+ Record Payment` (`#sp-kids-btn-record-payment`), replaced broken `#/school-fee-payment?billId=...` anchor links with inline `Collect` buttons (`openPaymentPopup`) and `Receipt` buttons on paid bills, added the admission **Payment Method** row to the Course tab, and added a 9-column **Chronological Payment Transactions** table (`#sp-kids-txns-tbody`) showing Date, Receipt no, Type, Mode pill, TXN ID, Collector, Remarks, and Receipt link (with `kidsPaymentsHydrated` loading indicator when `kidsHistory` cache was invalidated by a recent mutation).

## 4. Known Gaps, Behaviour Notes & Items NOT Changed

- **Transaction / Reference ID rule note (matched to Youth):** In `components/payment-popup.js`, Youth Centre disables `txnInput` on `Cash` (`N/A for Cash`) and enables `txnInput` on `UPI` / `Card` / `Bank Transfer` / `Cheque` with `(Optional)` (`txnInput.required = false`, never blocks submission if blank). To obey both `"same rules as Youth"` and `"don't change the Youth Centre's behaviour"`, `v1.8.197` kept that exact shared rule. If non-cash TXN ID should become strictly mandatory for Kids (or both programmes), that requires explicit approval.
- **Level Upgrade Modal (`school-break-modals.js`):** When upgrading a Kids student's level with a positive admission fee difference via `openKidsUpgradePackageModal` on Student Profile, that modal still uses its own inline confirmation checkbox rather than `openPaymentPopup` (listed below under larger parity items for approval).
- **Live Deploy Pending Approval:** Changes are committed and pushed to `main`, **not yet deployed** (`firebase deploy` not run without your explicit confirmation). Note also `v1.8.196` index additions in `firestore.indexes.json` remain pending deploy.
